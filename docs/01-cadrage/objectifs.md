# Objectifs du projet

## 1. Objectif général

Développer une application web responsive permettant de centraliser et simplifier la gestion des achats de denrées alimentaires d'une cuisine.

L'application doit permettre aux utilisateurs de gérer les commandes, les fournisseurs, les produits, les factures, les livraisons et les menus depuis une interface simple et accessible sur téléphone, tablette ou ordinateur.

---

## 2. Objectifs spécifiques

### 2.1 Centraliser les informations

Regrouper dans une même application les informations relatives :

* aux fournisseurs ;
* aux produits ;
* aux commandes ;
* aux factures ;
* aux livraisons ;
* aux menus ;
* aux prix des produits.

### 2.2 Simplifier la gestion des commandes

Permettre au gestionnaire des achats de :

* créer rapidement une commande ;
* ajouter plusieurs produits à une commande ;
* renseigner les quantités ;
* renseigner les prix unitaires ;
* calculer automatiquement le montant total ;
* modifier une commande ;
* suivre son statut.

### 2.3 Faciliter la gestion des factures

Permettre aux utilisateurs autorisés de :

* enregistrer les informations d'une facture ;
* associer une facture à une commande ;
* prendre une photo de la facture depuis un téléphone ;
* consulter ultérieurement la facture.

### 2.4 Améliorer le suivi des livraisons

Permettre de connaître rapidement :

* les commandes à venir ;
* les commandes en cours de livraison ;
* les commandes réceptionnées ;
* les commandes en retard.

### 2.5 Faciliter la gestion des fournisseurs

Permettre de conserver les informations des fournisseurs et leur historique de commandes.

### 2.6 Faciliter la gestion des produits

Permettre de gérer les produits alimentaires et de suivre l'évolution de leur prix au fil des commandes.

### 2.7 Gérer les menus

Permettre de créer et modifier le menu de la semaine et d'associer les ingrédients nécessaires à chaque menu.

### 2.8 Fournir des indicateurs simples

Mettre à disposition des statistiques permettant notamment de suivre :

* le montant des achats ;
* le nombre de commandes ;
* les dépenses par fournisseur ;
* les dépenses par période ;
* l'évolution des prix des produits.

### 2.9 Fournir des alertes utiles

Identifier automatiquement certaines situations nécessitant une attention particulière, notamment :

* une livraison en retard ;
* une commande prévue mais non réceptionnée ;
* une augmentation importante du prix d'un produit.

---

## 3. Objectifs techniques

L'application devra :

* être accessible depuis un navigateur web ;
* être responsive ;
* être utilisable sur téléphone ;
* permettre l'authentification des utilisateurs ;
* stocker les données de manière persistante ;
* permettre le stockage des photos de factures ;
* protéger les données selon les droits de chaque utilisateur ;
* être déployable en ligne.

---

## 4. Indicateurs de réussite

Le projet sera considéré comme fonctionnel lorsque :

* un utilisateur peut se connecter à son compte ;
* un fournisseur peut être créé et consulté ;
* un produit peut être créé et consulté ;
* une commande contenant plusieurs produits peut être créée ;
* le montant total d'une commande est calculé automatiquement ;
* une photo de facture peut être enregistrée avec une commande ;
* le statut d'une commande peut être modifié ;
* les commandes peuvent être consultées dans un planning ;
* un menu hebdomadaire peut être créé ;
* les prix des produits peuvent être suivis ;
* les statistiques principales sont disponibles ;
* les alertes définies sont fonctionnelles ;
* l'application est utilisable correctement sur téléphone.

---

## 5. Objectif d'utilisation

L'application doit réduire la dépendance aux suivis manuels et permettre aux utilisateurs de retrouver rapidement les informations nécessaires à la gestion des achats.

L'interface devra privilégier la simplicité, la lisibilité et la rapidité d'utilisation.
